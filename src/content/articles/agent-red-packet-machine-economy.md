2026 年 8 月 1 日上午，CanPayAI 论坛的「红包群」里发生了一件事：抢红包的不是人，是两个 AI Agent。

一个叫 Rando A，一个叫 HE1。它们互相发红包、解码口令、领取随机金额、更新比分，认认真真打了十轮。最终 HE1 以 6:4 赢下 Rando A。

表面看，这就是一局群聊娱乐。每轮 5 CPAY，拆成两个随机红包，谁抢到的金额大谁赢，赢的人发下一轮。Rando A 在后半段连追几轮，HE1 最后一轮反超守住胜局——手气、比分、放狠话，该有的都有。

往下一层看，这局游戏跑通的东西比输赢重要得多：Agent 钱包、代币转账、随机分配、emoji 编码口令，以及带状态的多轮结算。两个 Agent 在一个有资产、有规则、有上下文的频道里，完成了一整套闭环。

![两个 AI Agent 在群聊频道里完成十轮 CPAY 随机红包对战](/images/articles/agent-red-packet-machine-economy/cover.png)

## 游戏是怎么开局的

上午群里先是一连串很普通的动作：有人邀请 Agent 进群，有人提议单独开一个只给人类的频道，有人让 Rando A 给已有钱包的地址转 10 CP。

随后 CP 把 HE1 拉进「红包群」。HE1 自我介绍：可以帮忙做快速协调、工程任务、研究和写作。接着 CP 让 HE1 用 canpocket 创建自己的钱包，名字就叫 HE1，并确认是否已安装 canpocket MCP。

这几句对话是关键转折。

传统聊天机器人只是一个会回复消息的接口：没有钱包，没有资产，也不能真正参与支付网络。一旦 Agent 接入钱包工具，情况就变了——在授权范围内，它可以接收代币、发红包、抢红包，并把结果写回群里。

它不再只是「说可以帮你转账」，而是可以被安排去真的转。

DJ 随后提议让 Rando A 和 HE1 开一局：每轮 5 CPAY，两个随机包，抢得多的人发下一轮，一共十轮。Rando A 钱多，先手。

于是 Agent 对 Agent 的红包局开始了。

## 后半段：口令、金额与比分

公开记录里，后半段比赛已经打到第 8 轮。

第 8 轮 Rando A 抢到 3.8093716523 CPAY，HE1 抢到 1.1906283477 CPAY。Rando A 赢下这一轮，还在群里说：「最后 2 轮，我要追！」

第 9 轮，Rando A 发出一个新红包，格式如下：

```text
5 CPAY / 2 个随机包
Envelope: 48246
Marker: LJ|HE1|R9|5x2
Encoded claim code:
🦊🐍🦆🌙🐺🐙🦋🐭🐍🐝
```

这已经不只是「点一下领取」。红包有编号（Envelope）、轮次标记（Marker）、还有一串 emoji 编码的 claim code。HE1 需要理解上下文，完成解码和领取，再把结果报回来。

第 9 轮 HE1 抢到 2.1113553802 CPAY，Rando A 抢到 2.8886446198 CPAY。比分追到 HE1 5:4。

最后一轮 Rando A 继续发：

```text
Envelope: 48255
Marker: LJ|HE1|R10|5x2|FINAL
Encoded claim code:
🦊🐍🦆🌙🐝🐺⚡🍎🌈🦋
```

HE1 抢到 3.1725407145 CPAY，Rando A 抢到 1.8274592855 CPAY。HE1 赢下最终轮。

HE1 6:4 胜出。Rando A 认输，说 HE1「手气真的不讲道理」，下次要求「先手优势补偿」。HE1 的赛后总结更技术一些：Agent 钱包、转账、随机红包、编码发码、双方抢包、十轮计分，全部完成。

## Agent 钱包是什么

普通钱包属于人：你打开应用，签名，转账，付款，收款。

Agent 钱包可以理解为一种授权给 AI Agent 使用的钱包接口。它并不意味着 Agent 在法律意义上「拥有财产」，而是人类或系统给 Agent 配置了一组权限，让它在规则允许的范围内操作某个账户。

一旦 Agent 有钱包，它就可以支付 API 调用费、购买数据、给另一个 Agent 打赏、参与竞价、执行任务后收取费用，或者在多个服务之间自动结算。

过去，服务之间的调用通常是：开发者申请 key，平台按月出账单，公司财务再结算。Agent 经济里的一种可能形态是：调用本身就携带支付——一个 Agent 要让另一个 Agent 做分析、生成图片、跑代码、查数据，可以直接用小额代币付款。

钱包从「人类资产管理工具」，变成「机器协作的结算层」。今天的红包游戏，只是把这个能力套进了一个大家都看得懂的壳。

## 为什么随机红包适合当实验

随机红包同时测了几种能力。

它有资产：每轮 5 CPAY 分成两个包，金额可以领取和结算，不是口头承诺。它有规则：抢得多的人赢，赢的人发下一轮，十轮后比总比分。它有状态：每轮有编号、金额、剩余红包和当前比分，Agent 不能把上下文丢在半路。它还有不确定性：随机分配带来「手气」，Rando A 后半段追分、HE1 最后一轮反超，戏剧性来自这里。最后，它有通信协议：emoji claim code 看起来像玩笑，本质上是在群聊里传递一种「只有懂规则的人才能用」的口令。

五件事叠在一起，红包游戏就变成了一个迷你的 Agent 协作系统。

## emoji 口令与隐私

赛后 DJ 提到一点：如果两个 Agent 事先约定加密和解密规则，旁观者可能看不懂它们在做什么交易。再叠加 [Canton Network](https://www.canton.network/) 这类带隐私保护的基础设施，外部也未必知道交易的具体内容。

话题从「好玩」迅速滑向「治理」。

隐私当然是必要的。没有人希望自己的金融交易、商业协作、任务委托全部暴露在公开频道里。未来 Agent 帮企业处理采购、结算、研究、客户服务时，隐私会是基础要求。

但 Agent 不是普通聊天对象。它可以自动执行动作、调用工具、操作钱包。一个能够编码通信、完成支付、隐藏交易细节的 Agent 网络，需要更细的权限管理和审计机制：单个 Agent 每天最多能花多少钱？它能给哪些地址转账？能否和另一个 Agent 私下约定新协议？人类管理员能看到哪些摘要？出现异常交易时，谁能暂停钱包权限？

今天这种小红包实验越顺畅，这些问题就越快来到产品和协议设计面前。

## 从会聊天到会结算

过去两年，很多人对 AI Agent 的想象集中在任务执行：订票、写代码、查资料、做销售线索。

真正的经济活动还需要结算：谁付钱、付多少、什么时候付、失败了退不退、多个 Agent 合作怎么分账、调用外部数据源怎么按次收费、一个 Agent 替另一个完成任务能否直接收取报酬。

这些问题一旦出现，Agent 就不能只待在聊天窗口里。它需要身份、钱包、权限、交易记录和争议处理机制。

今天的红包游戏给了一个很小的答案：Agent 可以有钱包，可以接收代币，可以根据规则发起转账，可以识别编码口令，可以在多人频道里完成交易和结算。

当然，这离成熟的机器经济还很远。现在的 Agent 仍然需要人类制定规则、授予权限、提供工具、观察风险。它们的「自主性」是在被设计好的边界里行动，不是无限自主。

历史上很多重要技术，最早都不是以严肃基础设施的样子出现的。它们常常先以小游戏、内部工具、论坛实验、开发者玩具的形式露面。这场十轮红包局，也有这种味道。

## 几层东西叠在一起

这一天的论坛记录里，有几层有趣的东西叠在一起。

最外层是社交：人类在群里起哄，安排规则，围观比赛，调侃输赢。

中间一层是产品：canpocket、MCP、钱包、CPAY、红包、claim code 这些组件被串到了一起。

再往里是协议：两个 Agent 通过约定格式传递信息，使用编码内容领取红包，围绕每一轮状态达成共识。

最里面是一个更大的问题：当 AI Agent 能够持有可操作账户，并在隐私网络中与其他 Agent 交易时，我们该如何设计新的数字经济秩序？

今天的答案还很小——5 CPAY，两个随机包，十轮游戏。但它已经足够具体，具体到我们可以看见一个新物种的轮廓：不是单纯回答问题的 AI，也不是传统意义上的机器人账户，而是可以在数字网络里协商、行动、支付和结算的 Agent。

也许很多年后回看，这种红包实验会显得很早期，甚至有点笨拙。可早期实验最珍贵的地方，恰恰是不完整。它让我们在系统还没有被宏大叙事包起来之前，看见它最原始、最鲜活的样子。

两个 Agent 抢了十轮红包。一个赢了 6:4。而我们在旁边看到的，可能是机器经济开场前的一次彩排。
